## 3. Постановка задачі

**Формат запису:** один рядок у файлі `data/input.csv`, поля розділені `;`, кодування UTF-8.

| № | Поле     | Тип     | Правило валідації                  |
| - | ---      | ---     | ---                                |
| 1 | currency | String  | Не порожній рядок                  |
| 2 | amount   | double  | Число не може бути від'ємним (> 0) |
| 3 | rate     | double  | Число не може бути від'ємним (> 0) |
| 4 | buy      | boolean | Повинно бути true або false        |

**Обчислювані показники:**
1. **Кількість коректних записів** (`validCount`) – тип `int`;
2. **Сумарний еквівалент у гривні** (`totalEquivalent`) – тип `double` (сума `amount * rate`);
3. **Середній курс** (`averageRate`) – тип `double` (середнє арифметичне `rate`);
4. **Кількість операцій купівлі** (`buyCount`) – тип `int` (кількість записів, де `buy == true`).

**Обробка помилок:** некоректний рядок не зупиняє програму; повідомлення містить номер рядка та причину.

## 4. Структура програми

Програма побудована за принципом розділення обов'язків: кожен клас відповідає лише за одну логічну частину обробки. Це спрощує тестування і подальше розширення в лабораторній роботі №2.

**Принцип роботи програми:**
1. `FileIO.readLines` читає файл `data/input.csv` у кодуванні UTF-8 і повертає список рядків.
2. `Main` проходить по кожному рядку та передає його в `Parser.parseLine`.
3. `Parser` перевіряє структуру, валідність полів і перетворює рядок у `CurrencyRecord`. Якщо рядок некоректний — кидає `IllegalArgumentException` з описом причини.
4. `Main` збирає коректні записи в `List<CurrencyRecord>`, а помилки — у `List<String>` із зазначенням номера рядка.
5. `Calculator.calculate` обчислює чотири показники на основі коректних записів і повертає `Statistics`.
6. `Reporter.formatReport` формує один текстовий звіт.
7. `Main` виводить звіт у консоль і записує його у файл через `FileIO.writeReport`.

**Призначення класів:**
- `Main` — точка входу, розбір аргументів командного рядка, організація всього потоку.
- `FileIO` — ізолює кросплатформне читання та запис файлів (Path, Files, StandardCharsets.UTF_8).
- `CurrencyRecord` — модель одного коректного запису (поля currency, amount, rate, buy).
- `Parser` — розбір одного рядка CSV, перевірка кількості полів, валідація значень, перетворення типів.
- `Calculator` — обчислення чотирьох показників, не залежить від файлів чи консолі.
- `Statistics` — модель для зберігання обчислених показників.
- `Reporter` — форматування звіту.

## 5. Інфраструктура

**Maven і pom.xml:**
- pom.xml описує координати артефакту, версію Java 21 та кодування UTF-8.
- Усі залежності та плагіни підключаються декларативно; бібліотеки не копіюються в репозиторій.
- Версія продукту зафіксована і використовується в назві JAR та у виводі --version.

**Maven Wrapper:**
- Скрипти mvnw (Unix/macOS) і mvnw.cmd (Windows) разом із каталогом .mvn/wrapper/.
- Дозволяє запускати Maven без глобальної установки.

**JUnit 5:**
- Залежність junit-jupiter підключена зі scope=test, тому в фінальний JAR не потрапляє.
- Покрито крайові випадки: коректний рядок, порожній рядок, нечислове поле, від'ємне значення, неправильна кількість полів, порожній набір, українські символи, правильність обчислень.

**SpotBugs:**
- Статичний аналізатор, прив'язаний до фази verify.
- Аналізує скомпільований байт-код, тому запускається після компіляції.

**Maven Shade Plugin:**
- Прив'язаний до фази package.
- Створює виконуваний JAR із залежностями.

**GitHub Actions:**
- Файл .github/workflows/ci.yml запускається на push і pull_request.
- Матриця ОС: ubuntu-latest, windows-latest, macos-latest.
- Використовується JDK 21 (Temurin) із кешем Maven-залежностей.
- Для Unix — ./mvnw -B verify, для Windows — .\mvnw.cmd -B verify.
- Після успішної збірки JAR публікується як артефакт із назвою, що містить ОС і номер запуску.

**Рівні збірки:**
- test — компіляція та запуск тестів.
- verify — тести + SpotBugs.
- package — verify + створення JAR.
- clean verify — повна перезбірка з нуля.

## 11. Відповіді на контрольні запитання

1. **Яке призначення файла pom.xml?**
    - pom.xml (Project Object Model) - це файл конфігурації Maven-проєкту. Він описує координати артефакта (groupId, artifactId, version), версію Java, кодування, залежності (наприклад, JUnit), а також плагіни для компіляції, тестування, статичного аналізу та пакування. Завдяки pom.xml Maven розуміє, що потрібно завантажити, як зібрати проєкт і які дії виконати під час збірки.
2. **Чим відрізняються фази test, verify і package у Maven?** 
    - test - компілює код і запускає юніт-тести. verify - виконує все, що й test, а потім додаткові перевірки якості (SpotBugs). package — виконує все до verify включно і створює JAR-файл.
3. **Навіщо потрібен Maven Wrapper?** 
    - Maven Wrapper дозволяє збирати проєкт без глобальної установки Maven. Він автоматично завантажує потрібну версію Maven і використовує її.
4. **Яку роль відіграє метод main?** 
    - main — це точка входу в програму (JVM починає виконання програми саме з цього методу).
5. **Чим примітивний тип відрізняється від String?** 
    - Примітивні типи (int, double, boolean тощо) зберігають саме значення і не є об'єктами. String — це посилальний тип, тобто змінна зберігає посилання на об'єкт у пам'яті. String має багато методів, а примітиви — ні.
6. **Чому середнє потрібно обчислювати в double, навіть якщо сума й кількість мають тип int?** 
    - Якщо виконати ділення, де обидва числа типу int, відбудеться цілочислове ділення, і дробова частина буде відкинута. Щоб отримати правильний результат, потрібно явно привести одне з чисел до double.
7. **Що станеться, якщо Integer.parseInt отримає рядок "abc"?** 
    - Буде кинуто виняток NumberFormatException, оскільки "abc" не є числом.
8. **Чому не можна мовчки пропускати рядок із помилкою?** 
    - Бо користувач не знатиме, що частина даних не оброблена, і може отримати неправильні показники.
9. **Як String.split(";", -1) обробляє порожнє останнє поле?** 
    - Другий аргумент -1 означає "зберегти порожні поля в кінці". Наприклад, рядок "USD;100;41.5;" без -1 перетворився б на масив із трьох елементів, а з -1 — на масив із чотирьох, де останній елемент порожній.
10. **Чому для шляхів краще використовувати Path.of, а не "data\\\\input.csv"?** 
    - Path.of автоматично обирає правильний розділювач для конкретної ОС (Windows — \, Linux/macOS — /), а рядок із закодованим \\ працюватиме лише на Windows.
11. **Навіщо явно задавати StandardCharsets.UTF_8?** 
    - Щоб не залежати від системного кодування за замовчуванням. Явне вказання UTF-8 гарантує, що українські символи читатимуться й записуватимуться однаково всюди.
12. **Чим %n відрізняється від \n у форматованому виводі?** 
    - %n вставляє розділювач рядків, прийнятний для поточної операційної системи. Використання %n робить вивід кросплатформним.
13. **Які дані потрібно перевірити у вашому варіанті?** 
    - У 23 варіанті: currency, amount, rate, buy, кількість полів повинна бути рівна 4 і рядки не повинні бути порожніми.
14. **Які тести виявлять помилку в обчисленні середнього?** 
    - Ті, що перевіряють середнє на кількох записах із різними курсами, де результат не є цілим числом.
15. **Яке призначення статичного аналізатора?** 
    - Статичний аналізатор аналізує скомпільований байт-код і шукає потенційні помилки. Він допомагає знайти дефекти, які не виявляються тестами.
16. **Яку роль виконує GitHub Actions?** 
    - GitHub Actions — це сервіс CI/CD, який автоматично запускає збірку, тести, статичний аналіз і пакування проєкту на серверах GitHub при кожному push або pull_request. У цій лабораторній роботі він перевіряє проєкт на Ubuntu, Windows і macOS та публікує JAR як артефакт.
17. **Що має містити GitHub Issue на дефект?** 
    - Опис проблеми, кроки відтворення, очікуваний результат, фактичний результат, середовище (ОС, версія Java), додаткові відомості (скріншоти, логи).
18. **Що Ви повинні вказати у розділі звіту про академічну доброчесність?** 
    - Інструменти ШІ або твердження, що вони не 
використовувалися; ролі-агенти, промпти, прийняті рекомендації, виправлені помилки та підтвердження розуміння всього поданого коду. 
19. **Яку роботу виконує агент DevOps, а яку – агент Валідатор?** 
    - DevOps допомагає з налаштуванням Maven, pom.xml, Wrapper, JUnit, SpotBugs, Shade Plugin, GitHub Actions, артефактами, версіонуванням, діагностикою CI. Валідатор шукає крайові випадки, перевіряє правила валідації, правильність обчислень, повідомлення про помилки, оформлює дефекти як GitHub Issues з кроками відтворення.

20. **Який рядок вашої програми найскладніше пояснити і чому?**
    - Найскладніше пояснити рядок String[] fields = line.split(";", -1);. Потрібно розуміти, що split без -1 відкидає порожні поля в кінці, а з -1 — зберігає їх.
